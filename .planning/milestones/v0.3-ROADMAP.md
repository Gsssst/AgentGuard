# Milestone v0.3: LangGraph Adapter

**Status:** ✅ SHIPPED 2026-09-04  
**Phases:** 7–10  
**Total Plans:** 10  
**Requirements:** 22/22 satisfied

## Overview

Integrate AgentGuard's guarded tool execution boundary into LangGraph through
an optional `GuardedToolNode`, while LangGraph remains the owner of routing,
graph state, checkpointing, and interrupt/resume lifecycle.

## Milestone Summary

### Key Decisions

- LangGraph owns graph routing, state, checkpointing, and interruption.
- AgentGuard owns the guarded Tool execution boundary.
- Adapter tools stay outside the Runtime global registry.
- Tool metadata is explicit and missing guards fail closed.
- Direct and approval nodes are split for replay-sensitive graphs.
- Compatibility claims remain bounded to versions tested locally.

### Issues Resolved

- Added explicit Runtime execution seams for adapter-owned tools.
- Preserved ordered, isolated multi-tool results across concurrency and locks.
- Added digest-bound, redacted, independently decidable approvals.
- Fixed duplicate approval results caused by `add_messages` appending both
  placeholder and final ToolMessages.

### Issues Deferred

- Complete adapter validation/approval audit-event timelines.
- Graph-level LoopGuard and terminal ReliabilityReport integration.
- Broad version matrix, distributed locks, remote approval service, and UI.

### Technical Debt Incurred

- Original approval arguments remain inside checkpointed machine state for
  digest recomputation; only the interrupt projection is redacted.
- Compatibility is verified only for Python 3.12.9, LangGraph 0.6.11, and
  LangChain Core 0.3.86.
- External tool side effects remain at-least-once-aware, not exactly-once.
